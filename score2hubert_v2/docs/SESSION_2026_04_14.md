## F0 outlier filter impact

F0 outlier filter (|GT f0 vs MIDI| > 200c → 0.1× weight) was supposed to reduce long-tail pitch errors.

Evidence it's working:
- **Training** f0 loss dropped from 0.028 (step 50) to 0.014 (step 75K) — about 2× Run 3's level
- JA f0_mae went 42.7c (step 2500) → 37.5c (step 70K), close to theoretical 30c GT noise floor
- ONIKU reached 23c f0_mae — below "theoretical floor" because ONIKU is pre-pitch-corrected so no GT noise

Audibility test pending (will be in RESULTS subsection).

## Metric bug found & fixed (mid-training)

Original `_per_sample_metrics` didn't filter `note_pitch > 0` when computing F0 cents, causing ZH f0_mae to report ~2870c (vs the correct ~58c). Bug fix applied to `src/training/trainer.py` mid-training — won't affect Run 4 (running process had old code cached) but will apply to Run 5+. `scripts/eval_per_lang_v2.py` created as authoritative post-training eval with correct filter.

**Lesson**: any "voiced" mask used for per-sample F0 reporting MUST include `note_pitch > 0`, not just `f0_target > 30`. Rest-voiced frames (breath carryover into rest notes) contaminate otherwise.
