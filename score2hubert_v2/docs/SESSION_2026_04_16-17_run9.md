## Final 4-way mute eval

`scripts/run9_final_eval.sh`：6 datasets × 2 samples × 4 internal variants × 4 mute strategies = 192 wavs on GPU in 81s.

4 个策略定义：

| 策略 | 机制 |
|---|---|
| **raw** | eval_audio.py 无任何 mute |
| **inline** | eval_audio.py --hubert-mute combined：pred_hubert[SP 帧]=0 再喂 RVC |
| **post** | apply_midi_mute.py on raw：音频层 amplitude gate（只 fade 音尾）|
| **both** | apply_midi_mute.py on inline：双保险 |

### 用户听感 verdict

1. **Post / both 非常接近 ceiling** —— 满意
2. **Inline 听起来无效** —— 和 raw 几乎一样
3. **原 post mute 有"音头 glitch"**：fix 为只 fade 音尾，删 rising fade + note-onset ramp

### 为什么 inline 无效（机制分析）

Run 9 的 SP 训练太成功了：
- `pred_hubert[SP 帧]` 已经 ≈ 0（训练 target 0 + data fix + forward fix 三重作用）
- Inline mute 把接近 0 的值强制变 0 → **mathematically ≈ no-op**
- 残留电音来自 **RVC 自身**（HiFi-GAN 对 F0 + 残留 HuBERT 微差敏感）
- Inline 只动 HuBERT 不动 F0 → catch 不到
- Post 在音频输出层 amplitude gate → catch RVC 产出一切

### 音头 glitch 修复

`apply_midi_mute.py` 改动：
- 删 rising edge fade（rest→voice 不做 fade-in）
- `NOTE_ONSET_FADE_MS` default: 5.0 → **0.0**（note→note pitch 切换不做 dip+ramp）
- 原因：fade-in 会和 RVC 的 transient content 冲突 → 产生可听 glitch（**不是软化**，是实际瞬时 artifact）
- Memory: `feedback_post_mute_audio_head.md`
